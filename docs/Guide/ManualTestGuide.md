# UnrealEditorBridge 수동 테스트 가이드

이 문서는 UnrealEditorBridge의 핵심 기능을 수동으로 검증하기 위한 테스트 절차를 정의한다.
총 9개의 테스트 시나리오를 순서대로 진행하며, 각 시나리오의 사전 조건, 수행 절차, 예상 결과를 명시한다.

---

## 사전 요구사항

테스트를 시작하기 전에 다음 조건이 충족되어야 한다:

| 항목 | 상태 확인 |
|------|-----------|
| **UE5 에디터** | Sample 프로젝트(`D:\UnrealEngine\Sample\Sample.uproject`)가 열려 있고, UnrealEditorBridge 플러그인이 활성화되어 있다 |
| **WPF 앱 빌드** | `dotnet build`가 성공한 상태이다 |
| **WPF 앱 미실행** | 테스트 시작 시점에 WPF 앱이 아직 실행되지 않은 상태이다 (Test 1에서 실행) |

### WPF 앱 실행 방법

```powershell
dotnet run --project src/UnrealEditorBridge.Wpf
```

### UE5 플러그인 활성화 확인

UE5 에디터에서 **편집 > 플러그인**을 열고 "Unreal Editor Bridge"가 활성화(체크)되어 있는지 확인한다.

---

## Test 1: Editor 인스턴스 탐색 (Discovery)

Discovery MMF(`UEB_Discovery`)를 통해 실행 중인 UE5 에디터 인스턴스를 찾을 수 있는지 검증한다.

### 수행 절차

1. WPF 앱을 실행한다.
2. 연결 패널에서 **새로고침** 버튼을 클릭한다.
3. 인스턴스 목록을 확인한다.

### 예상 결과

| 확인 항목 | 예상 값 |
|-----------|---------|
| 인스턴스 목록에 항목이 표시되는가 | "Sample" 프로젝트가 1개 이상 표시됨 |
| 표시 형식 | `Sample (PID: xxxxx)` 형태로 프로젝트명과 PID가 함께 표시됨 |
| MMF 이름 | `UEB_Sample_xxxxx` 형태의 MMF 이름이 확인됨 |
| 활성 상태 | 인스턴스가 활성(alive) 상태로 표시됨 (최근 5초 이내 Heartbeat) |

### 판정 기준

- **통과:** Sample 인스턴스가 목록에 표시되고, PID와 MMF 이름이 올바른 형식이다.
- **실패:** 목록이 비어있거나 인스턴스 정보가 표시되지 않는다.

---

## Test 2: 연결 (Connection)

선택한 에디터 인스턴스에 MMF를 통해 연결이 정상적으로 수립되는지 검증한다.

### 사전 조건

- Test 1이 통과하여 인스턴스가 목록에 표시된 상태이다.

### 수행 절차

1. 인스턴스 목록에서 Sample 인스턴스를 선택한다.
2. **연결** 버튼을 클릭한다.
3. 상태 텍스트의 변화를 관찰한다.

### 예상 결과

| 확인 항목 | 예상 값 |
|-----------|---------|
| 연결 시도 시 상태 텍스트 | `"연결 중..."` 으로 변경됨 |
| 연결 완료 시 상태 텍스트 | `"연결됨 - Sample"` 으로 변경됨 |
| 연결 버튼 | 비활성화(disabled) 상태로 변경됨 |
| 연결 해제 버튼 | 활성화(enabled) 상태로 변경됨 |

### 판정 기준

- **통과:** 상태가 `"연결됨 - Sample"`으로 전환되고, 오류 메시지가 없다.
- **실패:** 상태가 `"연결 오류"` 또는 `"프로토콜 버전 불일치"`로 표시되거나 연결 시도 후 무응답이다.

---

## Test 3: 에셋 스냅샷 조회 (Snapshot)

연결 후 Snapshot 영역에서 에셋 메타데이터를 정상적으로 읽어오는지 검증한다.

### 사전 조건

- Test 2가 통과하여 연결 상태(`"연결됨"`)이다.

### 수행 절차

1. 연결 직후 에셋 목록 패널을 확인한다.
2. 전체 에셋 개수를 확인한다.
3. 검색 필터에 키워드를 입력하여 필터링을 테스트한다.
4. 클래스 필터 드롭다운에서 특정 클래스를 선택한다.
5. **필터 초기화** 버튼을 클릭하여 필터를 해제한다.

### 예상 결과

| 확인 항목 | 예상 값 |
|-----------|---------|
| 에셋 목록에 항목이 표시되는가 | 3,000개 이상의 에셋이 표시됨 |
| 전체 개수 표시 | 전체 에셋 수(TotalCount)가 표시됨 |
| 검색 필터 동작 | 텍스트 입력 시 300ms 디바운싱 후 에셋 이름/경로가 일치하는 항목만 필터링됨 |
| 필터링된 개수 표시 | 필터 적용 후 FilteredCount가 TotalCount보다 작아짐 |
| 클래스 필터 동작 | 선택한 클래스에 해당하는 에셋만 표시됨 (예: `/Script/Engine.StaticMesh`만 표시) |
| 필터 초기화 | 필터 초기화 후 전체 에셋이 다시 표시됨 |

### 판정 기준

- **통과:** 3,000개 이상의 에셋이 표시되고, 검색 필터와 클래스 필터가 정상 동작한다.
- **실패:** 에셋 목록이 비어있거나, 필터가 동작하지 않거나, 에셋 수가 현저히 적다.

## Test 4: 에셋 상세 정보 (Asset Detail)

에셋 목록에서 선택한 항목의 상세 메타데이터가 올바르게 표시되는지 검증한다.

### 사전 조건

- Test 3이 통과하여 에셋 목록에 항목이 표시된 상태이다.

### 수행 절차

1. 에셋 목록에서 임의의 에셋을 선택한다.
2. 에셋 상세 패널의 각 필드를 확인한다.
3. 다른 에셋을 선택하여 정보가 갱신되는지 확인한다.

### 예상 결과

| 확인 항목 | 예상 값 |
|-----------|---------|
| **ObjectPath** | 비어있지 않은 경로가 표시됨 (예: `/Game/Characters/Hero/SK_Hero.SK_Hero`) |
| **PackagePath** | 에셋의 패키지 디렉토리 경로가 표시됨 (예: `/Game/Characters/Hero`) |
| **AssetName** | 에셋 이름이 표시됨 (예: `SK_Hero`) |
| **ClassName** | 에셋 클래스 경로가 표시됨 (예: `/Script/Engine.SkeletalMesh`) |
| **Tags** | 키-값 쌍의 태그 목록이 표시됨 (태그가 없는 에셋은 빈 목록) |
| **Dependencies** | Hard/Soft 의존성 경로 목록이 표시됨 (의존성이 없으면 빈 목록) |
| 선택 해제 시 | 에셋 선택을 해제하면 상세 패널이 비워짐 |

### 판정 기준

- **통과:** ObjectPath, PackagePath, ClassName, AssetName이 모두 비어있지 않으며, Tags와 Dependencies가 정상적으로 표시된다.
- **실패:** 상세 정보 필드가 비어있거나 `null`로 표시된다.

## Test 5: 실시간 이벤트 수신 (Real-time Events)

UE5 에디터에서 에셋 변경 작업을 수행했을 때 WPF 앱의 이벤트 로그에 실시간으로 반영되는지 검증한다.

### 사전 조건

- Test 2가 통과하여 연결 상태(`"연결됨"`)이다.
- WPF 앱의 이벤트 로그 패널이 보이는 상태이다.

### 수행 절차

1. UE5 에디터의 콘텐츠 브라우저에서 **우클릭 > 기본 에셋 > Material**을 선택하여 새 머티리얼을 생성한다.
2. WPF 앱의 이벤트 로그에 생성 이벤트가 표시되는지 확인한다.
3. 생성한 에셋을 삭제한다 (우클릭 > 삭제).
4. WPF 앱의 이벤트 로그에 삭제 이벤트가 표시되는지 확인한다.
5. 다른 에셋을 선택하고 이름을 변경한다 (F2 키).
6. WPF 앱의 이벤트 로그에 이름 변경 이벤트가 표시되는지 확인한다.

### 예상 결과

| 확인 항목 | 예상 값 |
|-----------|---------|
| 에셋 생성 시 | `[생성] NewMaterial` 형태의 로그 항목이 추가됨 |
| 에셋 삭제 시 | `[삭제] NewMaterial` 형태의 로그 항목이 추가됨 |
| 에셋 이름 변경 시 | `[이름변경] OldName --> NewName` 형태의 로그 항목이 추가됨 |
| 이벤트 순서 | 최신 이벤트가 목록 상단에 표시됨 |
| 타임스탬프 | 각 이벤트에 UTC 시각이 기록됨 |
| 시퀀스 번호 | 각 이벤트의 SequenceNumber가 단조 증가함 |

### 판정 기준

- **통과:** UE5 에디터에서의 에셋 변경이 3초 이내에 이벤트 로그에 반영된다.
- **실패:** 이벤트가 수신되지 않거나, 이벤트 타입이 올바르지 않다.

## Test 6: 이벤트 타입 검증 (Event Types)

지원하는 주요 이벤트 타입(`AssetCreated`, `AssetDeleted`, `AssetRenamed`, `AssetSaved`)이 각각 올바르게 분류되어 표시되는지 검증한다.

### 사전 조건

- Test 2가 통과하여 연결 상태이다.

### 수행 절차

다음 작업을 UE5 에디터에서 순서대로 수행하고, 각각에 대응하는 이벤트 타입을 WPF 앱에서 확인한다:

| 단계 | UE5 에디터 작업 | 예상 이벤트 타입 | 이벤트 로그 표시 형식 |
|------|-----------------|------------------|----------------------|
| 1 | 콘텐츠 브라우저에서 새 Material 생성 | `AssetCreated` | `[생성] MaterialName` |
| 2 | 생성한 Material을 열고 저장 (Ctrl+S) | `AssetSaved` | `[저장] MaterialName` |
| 3 | Material 이름 변경 (F2) | `AssetRenamed` | `[이름변경] OldName --> NewName` |
| 4 | Material 삭제 | `AssetDeleted` | `[삭제] MaterialName` |

### 예상 결과

| 확인 항목 | 예상 값 |
|-----------|---------|
| AssetCreated 이벤트 | EventType = `AssetCreated (1)`, AssetName과 ClassName이 비어있지 않음 |
| AssetSaved 이벤트 | EventType = `AssetSaved (4)`, AssetName이 비어있지 않음 |
| AssetRenamed 이벤트 | EventType = `AssetRenamed (3)`, OldObjectPath와 OldAssetName이 유효함 |
| AssetDeleted 이벤트 | EventType = `AssetDeleted (2)`, ObjectPath가 비어있지 않음 |
| 이벤트 필터 동작 | 이벤트 로그 패널의 이벤트 타입별 체크박스(생성/삭제/이름변경/저장)로 표시 여부를 제어할 수 있음 |

### 판정 기준

- **통과:** 4가지 이벤트 타입이 모두 올바르게 수신되고, 이벤트 필터 체크박스가 정상 동작한다.
- **실패:** 특정 이벤트 타입이 수신되지 않거나, 이벤트 필터가 동작하지 않는다.

## Test 7: 연결 해제 및 재연결 (Disconnect / Reconnect)

연결 해제 시 UI 상태가 초기화되고, 재연결 시 데이터가 복원되는지 검증한다.

### 사전 조건

- Test 3이 통과하여 에셋 목록이 표시된 연결 상태이다.

### 수행 절차

1. 현재 에셋 목록의 전체 에셋 개수를 기록해 둔다.
2. **연결 해제** 버튼을 클릭한다.
3. UI 상태 변화를 확인한다.
4. 다시 인스턴스 목록에서 Sample을 선택하고 **연결** 버튼을 클릭한다.
5. 재연결 후 에셋 목록이 복원되는지 확인한다.

### 예상 결과

**연결 해제 시:**

| 확인 항목 | 예상 값 |
|-----------|---------|
| 상태 텍스트 | `"연결 안됨"` 으로 변경됨 |
| 에셋 목록 | 비어있음 (목록이 클리어됨) |
| 에셋 상세 패널 | 비어있음 |
| 이벤트 로그 | 이전 이벤트는 유지되나 새 이벤트가 추가되지 않음 |
| 연결 버튼 | 활성화됨 |
| 연결 해제 버튼 | 비활성화됨 |

**재연결 시:**

| 확인 항목 | 예상 값 |
|-----------|---------|
| 상태 텍스트 | `"연결됨 - Sample"` 으로 변경됨 |
| 에셋 목록 | 이전과 동일한 수의 에셋이 다시 표시됨 |
| 검색/필터 기능 | 정상 동작함 |

### 판정 기준

- **통과:** 연결 해제 시 UI가 정상적으로 초기화되고, 재연결 시 동일한 데이터가 복원된다.
- **실패:** 연결 해제 후 UI가 초기화되지 않거나, 재연결이 실패한다.

## Test 8: 에디터 종료 처리 (Editor Shutdown)

UE5 에디터가 종료되었을 때 WPF 앱이 상태 전환을 올바르게 처리하는지 검증한다.

### 사전 조건

- Test 2가 통과하여 연결 상태(`"연결됨"`)이다.

### 수행 절차

1. WPF 앱이 `"연결됨"` 상태인지 확인한다.
2. UE5 에디터를 닫는다 (파일 > 종료 또는 창 닫기).
3. WPF 앱의 상태 텍스트 변화를 관찰한다 (최대 10초간).

### 예상 결과

| 확인 항목 | 예상 값 |
|-----------|---------|
| 1차 상태 전환 | `"응답 없음 - 재연결 대기 중"` (Lost 상태)으로 변경됨 |
| 2차 상태 전환 | `"연결 안됨"` (Disconnected 상태)으로 변경됨 |
| 상태 전환 시간 | Heartbeat 타임아웃(약 5초) 이후 Lost로 전환, 이후 Disconnected로 전환 |
| WPF 앱 안정성 | 예외(Exception)나 크래시 없이 정상 유지됨 |

### 판정 기준

- **통과:** Lost 상태를 거쳐 Disconnected 상태로 정상 전환되며, WPF 앱이 크래시 없이 안정적이다.
- **실패:** 상태 전환이 발생하지 않거나, WPF 앱이 크래시되거나 무한 대기 상태에 빠진다.

> **참고:** 이 테스트 이후 재테스트를 위해서는 UE5 에디터를 다시 실행해야 한다. 에디터 재실행 후 Test 1부터 다시 진행하여 정상 동작을 확인한다.

---

## Test 9: 스냅샷 새로고침 (Snapshot Refresh)

이미 연결된 상태에서 스냅샷 새로고침 버튼으로 최신 데이터를 다시 조회할 수 있는지 검증한다.

### 사전 조건

- Test 3이 통과하여 에셋 목록이 표시된 연결 상태이다.

### 수행 절차

1. 현재 에셋 목록의 전체 에셋 개수를 기록한다.
2. UE5 에디터에서 콘텐츠 브라우저를 통해 새 에셋(Material 등)을 2~3개 생성한다.
3. WPF 앱의 에셋 목록 패널에서 **새로고침** 버튼을 클릭한다.
4. 에셋 목록이 갱신되는지 확인한다.

### 예상 결과

| 확인 항목 | 예상 값 |
|-----------|---------|
| 전체 에셋 개수 변화 | 새로 생성한 에셋 수만큼 증가함 |
| 새 에셋 표시 | 새로 생성한 에셋이 목록에 포함됨 |
| 클래스 필터 목록 갱신 | AvailableClasses 드롭다운에 새 에셋의 클래스가 포함됨 |
| 검색 필터 동작 | 새 에셋 이름으로 검색 시 해당 에셋이 필터링됨 |
| 기존 데이터 유지 | 기존 에셋 정보가 사라지지 않고 유지됨 |

### 판정 기준

- **통과:** 새로고침 후 새로 생성한 에셋이 목록에 반영되고, 전체 개수가 정확하다.
- **실패:** 새로고침 후에도 목록이 갱신되지 않거나, 기존 데이터가 유실된다.

## 문제 해결 (Troubleshooting)

### 인스턴스가 목록에 표시되지 않는 경우

1. **플러그인 활성화 확인:** UE5 에디터에서 편집 > 플러그인에서 "Unreal Editor Bridge"가 활성화(체크)되어 있는지 확인한다.
2. **에디터 재시작:** 플러그인을 처음 활성화한 경우 에디터를 재시작해야 한다.
3. **Discovery MMF 확인:** 플러그인이 로드되면 `UEB_Discovery` 이름의 Memory-Mapped File이 생성된다. 시스템 도구로 MMF 존재 여부를 확인할 수 있다.
4. **방화벽/보안 소프트웨어:** 일부 보안 소프트웨어가 프로세스 간 MMF 공유를 차단할 수 있다. 해당 소프트웨어의 로그를 확인한다.

### 연결이 실패하는 경우

1. **프로토콜 버전 확인:** 상태 텍스트가 `"프로토콜 버전 불일치"`인 경우, C# 프로젝트와 UE5 플러그인의 프로토콜 버전(`ProtocolVersion = 1000`, v1.0)이 일치하는지 확인한다.
2. **MMF 이름 유효성:** 인스턴스의 MMF 이름이 `UEB_Sample_xxxxx` 형식인지 확인한다.
3. **권한 문제:** WPF 앱과 UE5 에디터가 동일한 사용자 세션에서 실행 중인지 확인한다. 다른 사용자 계정에서는 MMF에 접근할 수 없다.

### 에셋 목록이 비어있는 경우

1. **연결 상태 확인:** 상태 텍스트가 `"연결됨"`인지 확인한다.
2. **스냅샷 크기 확인:** UE5 프로젝트에 콘텐츠가 있는지 확인한다. 빈 프로젝트는 에셋이 매우 적을 수 있다.
3. **새로고침 시도:** 에셋 목록의 새로고침 버튼을 클릭하여 스냅샷을 수동으로 다시 요청한다.

### 이벤트가 수신되지 않는 경우

1. **이벤트 필터 확인:** 이벤트 로그 패널의 이벤트 타입별 체크박스(생성/삭제/이름변경/저장/기타)가 모두 활성화되어 있는지 확인한다.
2. **연결 상태 확인:** Lost 상태에서는 새 이벤트가 수신되지 않을 수 있다.
3. **이벤트 오버플로:** 대량의 에셋 변경 작업 후 `"이벤트 N건 누락"` 경고가 표시되면, Ring Buffer 오버플로가 발생한 것이다. 이 경우 스냅샷 새로고침을 수행하여 최신 상태로 동기화한다.
4. **에디터 작업 범위:** 에디터 외부(파일 탐색기 등)에서의 파일 변경은 AssetRegistry에 즉시 반영되지 않을 수 있다. 반드시 UE5 에디터 내 콘텐츠 브라우저에서 작업한다.

### WPF 앱이 크래시되는 경우

1. **로그 확인:** 콘솔 출력이나 `dotnet run` 터미널의 오류 메시지를 확인한다.
2. **클린 빌드:** `dotnet clean && dotnet build`로 클린 빌드를 수행한 뒤 재실행한다.
3. **에디터 먼저 실행:** WPF 앱을 실행하기 전에 UE5 에디터가 완전히 로드되었는지 확인한다.

### Lost 상태에서 복구되지 않는 경우

1. **에디터 프로세스 확인:** 작업 관리자에서 UE5 에디터 프로세스가 실행 중인지 확인한다.
2. **연결 해제 후 재연결:** WPF 앱에서 연결 해제 버튼을 클릭한 뒤, 인스턴스 목록을 새로고침하고 재연결을 시도한다.
3. **Heartbeat 타임아웃:** Lost 상태는 Heartbeat가 5초 이상 미수신될 때 발생한다. 에디터가 무거운 작업(셰이더 컴파일 등)을 수행 중이면 일시적으로 Lost 상태가 될 수 있으며, 작업 완료 후 자동 복구될 수 있다.
